# แผนยกระดับเว็บเซอร์ไพรส์ข้าวหอม — “เดินทางทะลุห้วงอวกาศ”

เอกสารส่งให้ Codex ทำงานต่อจากโค้ดปัจจุบัน โดยแบ่งเป็นเฟสที่ตรวจผลได้ ไม่รื้อทุกอย่างพร้อมกัน
เป้าหมายคือประสบการณ์วันเกิด 3D โทนม่วงที่มีภาพยนตร์นำทางเข้ากาแล็กซีและดาว **ดาวลูกหมู-001** ภาพชัด อ่านง่าย ดูมีมิติ และเล่นได้ลื่นทั้งมือถือกับคอมพิวเตอร์

## เป้าหมายด้านภาพ

ทำให้ผู้ชมรู้สึกว่าเริ่มจากความมืดในอวกาศ ค่อย ๆ เดินทางผ่านประตูมิติ เห็นกาแล็กซีเปิดออก แล้วมาถึงระบบดาวของข้าวหอม จุดเด่นต้องอ่านออกในไม่กี่วินาที: ดาว/หัวใจหลัก, ดาวเคราะห์, วงโคจร และข้อความอวยพร

แนวภาพให้เหมือน **ภาพถ่ายอวกาศแบบภาพยนตร์ + แสงม่วงของขวัญวันเกิด** ไม่ใช่ฉากนีออนที่ทุกชิ้นเรืองแสงพร้อมกัน ภาพต้องคมและมีจุดมืดไว้พักสายตา เก็บเอฟเฟกต์ฟุ้งไว้เฉพาะแหล่งกำเนิดแสงสำคัญ

ไม่มีวิธีรับประกันว่าทุกคนจะชม แต่แผนนี้ออกแบบให้ได้ช็อตเปิดตัวและช็อตจบที่จำง่าย พร้อมสัดส่วนสำหรับโพสต์แนวตั้ง/แนวนอน

## 1. ตรวจสภาพโค้ดและภาพปัจจุบัน

### สิ่งที่มีอยู่แล้ว

- เว็บใช้ Vite และ Three.js (`three` 0.169), GSAP และ EffectComposer
- มี `OutputPass`, `UnrealBloomPass`, MSAA เมื่อรองรับ และ `NeutralToneMapping`
- มีระบบดาวฉากหลัง, กาแล็กซีอนุภาค, ระบบดาวรูปหัวใจ, พลุดาว, wormhole แบบ shader และชื่อ “ข้าวหอม”
- มีปรับคุณภาพตามอุปกรณ์, กล้องตาม aspect ratio, query flags, visual QA ด้วย Playwright และการพัก render เมื่อแท็บซ่อน
- ไฟล์เพลงที่อยู่ในโปรเจกต์คือ `public/audio/velika-official-audio.mp3`
- มีฉากเก่าที่ไม่ import ใน `legacy/scene/` เก็บไว้แล้ว

### ปัญหาที่เห็นจากการอ่านโค้ดและภาพ QA

1. **ภาพเปิดยังกระจายและมีพื้นที่ว่างมาก**: HUD หนาและเด่นกว่าฉาก ขณะที่วัตถุสำคัญไม่รวมเป็นกลุ่มเดียวกัน
2. **องค์ประกอบหลุดกรอบ**: บน desktop มีดาวเสาร์/ดาวอังคารชิดหรือหลุดขอบ และบนมือถือดาวหลายดวงถูกตัด วงโคจรบางส่วนกว้างเกินพื้นที่จอ กล้องเริ่มต้นยังไม่ได้ fit ตามขอบเขตของฉากจริง
3. **ดาวเคราะห์ยังดูเป็นภาพวาด/พลาสติก**: `createPlanetTexture()` วาดผิวด้วย Canvas และรูปทรงพื้นผิวเรียบง่าย ไม่มี normal/roughness/cloud maps ที่สมจริง
4. **แสงยังไม่เป็นระบบเดียวกัน**: สีม่วงและจุดสว่างจัดตัดกับด้านมืดมาก ผิวดาวบางด้านดำหรือสีอิ่มจนรายละเอียดหาย ต้องจัด key/fill/rim ใหม่และดูบน GPU จริง
5. **วงโคจรเป็นเส้นบาง**: `THREE.Line` ไม่ได้หนาขึ้นตาม line width บน WebGL ทำให้เส้นอ่านเป็นลวดผม และวงหลายวงซ้อนกันจนแย่งความสนใจ
6. **กาแล็กซีมีอนุภาคจำนวนมากแต่ยังไม่เป็นมวลอวกาศลึก**: จุดดาวและ nebula แบบ sprite ช่วยสร้างสี แต่ยังขาดชั้น foreground/midground/background, dust lane และความรู้สึก parallax/ความลึก
7. **ประตูมิติมีพื้นฐาน shader แล้ว** แต่ยังควรผูกกับการเคลื่อนกล้อง/เสียง/จังหวะเล่าเรื่องและลดเส้น warp ที่ยาวรกในบางช่วง
8. **ชื่อ “ข้าวหอม” ดูจางในระยะไกล**: `name3DText.js` ใช้ canvas texture บน Plane ซ้อน 10 ชั้น ไม่ใช่ตัวอักษร 3D extrude จริง และมี glow สีแดงรอบตัว
9. **ตัวเลข FPS จาก Playwright ปัจจุบันมาจาก SwiftShader**: ใช้ตรวจ error และ layout ได้ แต่ห้ามใช้เป็นผลยืนยัน FPS บนอุปกรณ์จริง

ภาพ QA ปัจจุบัน: `qa/handoff/desktop.png`, `qa/handoff/portrait.png`, `qa/handoff/mobile.png`, `qa/handoff/galaxy-desktop.png` ให้เปิดเทียบก่อนเริ่มและเก็บภาพใหม่ทุกเฟส

## 2. ข้อกำหนดที่ห้ามหลุด

- รักษาลำดับประสบการณ์: หน้า Happy Birthday → กดเริ่ม/ท่องกาแล็กซี → เดินทาง → ถึงดาวลูกหมู-001 → เปิดคำอวยพร/ความทรงจำ
- คงข้อความเดิมใน `src/config/memoriesData.js` และข้อความ UI ภาษาไทย เว้นแต่ผู้ใช้สั่งให้แก้
- คง API ที่ `src/main.js` เรียกใช้ หรืออัปเดตทุก call site ให้ครบ เช่น `galaxy.triggerGrandShower`, `solarSystem.planetsList / interactiveMeshes / setHover / markVisited`, `fireworks.triggerMakeAWish`, `name3DText.show/hide`
- เพลงต้องเริ่มหลังผู้ชมกดหรือยินยอมให้เล่น มีปุ่มหยุด/ปิดเสียงและไม่ autoplay ฝ่าฝืนข้อจำกัดเบราว์เซอร์
- ตรวจ branch และ `git status` ก่อนแก้ ห้ามทับงานที่ยังไม่ commit
- ห้ามนำ texture/model/font จากเว็บมาใช้โดยไม่เช็ก license และบันทึกใน `CREDITS.md`
- คงทางเลือก `prefers-reduced-motion` และ fallback สำหรับอุปกรณ์ที่ WebGL/float render target ไม่รองรับ
- ทำทีละเฟส; จบแต่ละเฟสรัน `npm run build`, ตรวจ screenshot, บันทึกผลและไฟล์ที่แก้ อย่าเขียนว่า “ผ่าน” จากการ build อย่างเดียว

## 3. ทิศทางศิลป์และองค์ประกอบภาพ

### จานสีและแสง

- พื้นหลัง: midnight navy/indigo เกือบดำ
- สีเน้นหลัก: violet/lavender; ใช้ magenta เป็นสีรองสำหรับอารมณ์และสีขาวนวลสำหรับจุดสว่าง
- สีดาวเคราะห์ควรอิงลักษณะจริงของดาว แล้วแทรกม่วงในฉาก/ขอบแสง ไม่ย้อมทุกพื้นผิวเป็นม่วง
- ใช้แหล่งกำเนิดแสงกลางฉากหนึ่งจุดเป็น key light, fill อ่อนมาก, rim light จำกัดทิศทาง และ environment reflection สำหรับวัสดุโลหะ/คริสตัล
- Bloom ให้เกิดเฉพาะ pixel ที่สว่างกว่าค่ากำหนด ทดลอง strength ต่ำก่อน (ประมาณ 0.15–0.35) แล้วดูภาพ ไม่ใช้ bloom แก้การจัดแสงหรือทำให้ทุกดวงมี halo

### ลำดับชั้นสายตา

1. ตอนเปิด: Happy Birthday และปุ่มเริ่มต้องอ่านง่ายบนภาพฉากหลังที่สงบ
2. ระหว่างเดินทาง: wormhole เป็นพระเอก; ซ่อน HUD ที่ไม่จำเป็น
3. ถึงระบบดาว: หัวใจ/ดาวลูกหมู-001 เป็นจุดเด่น วงโคจรเป็นกรอบนำสายตา ดาวเคราะห์ทุกดวงต้องอยู่ใน safe frame
4. ข้อความ/การ์ดความทรงจำต้องไม่บังวัตถุและอ่านได้บนมือถือ
5. พลุดาวเกิดเมื่อกดคำอวยพร แล้วจบไวพอให้กลับมาเห็นดาวและข้อความหลัก

## 4. แผนทำงานตามลำดับ

### P0 — Baseline และวัดผลก่อนแก้

- ตรวจ branch, `git status`, รายการ asset และคำสั่งที่ใช้งานได้
- รัน `npm run build` และ `npm run visual:qa -- --phase=baseline`
- บันทึก screenshot 1920×1080, 1080×1920 และ 390×844 ทั้งหน้าเริ่ม, system view และ galaxy view
- ตรวจ console error, WebGL context, layout overflow, ปุ่มบนมือถือ และ state ของเพลง
- เปิด `?debug=1` บันทึก FPS/draw calls/GPU memory บนเครื่องจริงหนึ่งเครื่อง (desktop) และมือถือหนึ่งเครื่องถ้ามี

**ผ่านเมื่อ:** baseline ครบทุก viewport; มีรายการปัญหาที่ทำซ้ำได้; ยังไม่มีการแก้เนื้อหา/ข้อความโดยไม่ตั้งใจ

### P1 — จัดองค์ประกอบและสัดส่วนหน้าจอ (ทำก่อนเพิ่มรายละเอียดกราฟิก)

- สร้าง camera framing จาก bounding volume ของ heart + วงโคจร + ดาวเคราะห์ ไม่ใช้ค่า aspect อย่างเดียว
- กำหนด safe frame ของ HUD ให้ฉาก 3D ไม่ถูกทับ และกันระยะ notch/safe area
- Desktop: รวบกลุ่มวัตถุไว้กลางเฟรม ให้เห็นวงโคจรพอดีและดาวหลักมีขนาดพออ่านพื้นผิว
- Portrait: จัดเป็นองค์ประกอบสูงแบบ cinematic; ลด/ซ่อนวงรอบนอกใน hero หรือทำภาพนำเสนอ portrait แยก ไม่บีบให้ระบบทั้งหมดเล็กจนมองไม่เห็น
- ให้ผู้ชมยังลาก/หมุนดูได้ และเพิ่มปุ่มกลับมุมจัดวางที่ปลอดภัย
- ลดขนาด/จำนวน HUD, จัด typography และ contrast ให้ปุ่มหลักเด่นเพียงปุ่มเดียวในแต่ละช่วง

**ผ่านเมื่อ:** วัตถุสำคัญไม่ถูกตัดที่สาม viewport, ข้อความ/ปุ่มไม่ซ้อนฉากหรือกันเอง, ไม่มี horizontal scroll

### P2 — แสง วัสดุ และดาวเคราะห์สมจริงขึ้น

- แยก material/lighting ของวัตถุหลักให้เข้าใจง่ายและตั้งค่าจาก config เดียว
- ตั้ง color management ให้สอดคล้อง: color textures เป็น sRGB, maps ที่เป็นข้อมูลไม่แปลงสี, tone mapping/output pass มีเพียงหนึ่งครั้ง
- ปรับ key light ที่ตำแหน่งดวงอาทิตย์กลางระบบ แล้วเติม fill เบา ๆ ให้ด้านเงายังเห็นรูปทรงโดยไม่ลบเงา
- ดาวแต่ละดวงควรมีพื้นผิวที่เหมาะกับชนิด: โลกมีมหาสมุทร/ทวีป/เมฆ, ดาวอังคารมีสีสนิม/ขั้ว, พฤหัสมีแถบเมฆ, เสาร์มีวงแหวนโปร่งแสงและช่องว่าง Cassini
- ตัวเลือก asset: ใช้แผนที่ดาวจาก NASA/ESA หรือ Solar System Scope เมื่อ license ชัด; หากยังไม่มี ให้ทำ procedural texture แบบ noise/fbm ที่มี seed คงที่และสร้าง normal/roughness แบบเบา
- เพิ่ม atmosphere rim ด้วย shader Fresnel บาง ๆ เฉพาะโลก/ดาวที่สมเหตุผล ห้ามทำเป็นวง glow ฟุ้งหนา
- หัวใจคริสตัลต้องสะท้อน environment ที่เตรียมไว้ (procedural cubemap หรือ HDRI ที่ license อนุญาต) และยังคงอ่านเป็นหัวใจ ไม่ใช่ลูกบอลพลาสติก

**ผ่านเมื่อ:** เห็นด้านสว่าง/เงาของดาวชัด, texture ไม่เปลี่ยนทุก reload, รายละเอียดไม่หายเมื่อย่อภาพ, มีภาพเทียบก่อน/หลังและผ่าน desktop/mobile

### P3 — วงโคจรสวยและนำสายตา

- แทน `THREE.Line` ด้วย ribbon mesh หรือ shader strip ที่ควบคุมความกว้างเป็น world/screen space ได้และ antialias ดี
- ใช้วงรีและระนาบเอียงต่างกันอย่างพอดี; อย่าซ้อนศูนย์กลางทุกวงจนดูเป็นลายกราฟ
- กำหนดสี/ความสว่างตามลำดับดาว: วงในบางและจาง, วงดาวหลักเด่นขึ้นเล็กน้อย, วงที่ไม่ active ลด opacity
- เพิ่ม tick/เม็ดแสง/อนุภาคนำทางเฉพาะบางตำแหน่ง (ไม่ใช้แถบเรืองทั้งเส้น)
- ขณะเปิดการ์ดให้หยุด/ชะลอวงโคจรหรือ lock ดาวที่โฟกัส เพื่อไม่ให้หลุดเฟรมระหว่างอ่าน
- ตรวจ raycast: เส้น/particle ที่ตกแต่งต้องไม่ขวางการคลิกดาว

**ผ่านเมื่อ:** วงอ่านเป็นวงโคจรมีความลึก ไม่แย่งจากดาว และใช้งานบนมือถือได้

### P4 — กาแล็กซีลึกและสมจริง

- จัดเป็น 4–5 ชั้น: starfield ระยะไกลแบบนิ่ง, dust lane มืด, spiral arms, nebula filament/ionized gas, foreground star น้อย ๆ สำหรับ parallax
- เปลี่ยนจากจุดกระจายสม่ำเสมอเป็น radial density ตามแขนกังหัน มีแกนสว่างแต่ไม่ขาวล้น และมีช่องฝุ่นมืดตัดแขน
- ใช้ particle shader/GPU สำหรับดาวขนาดเล็ก และ instancing สำหรับชิ้นที่ซ้ำ; หลีกเลี่ยงสร้าง Mesh แยกหลายหมื่นชิ้น
- nebula ใช้ noise texture/volume impostor ที่มีรูปทรงไม่ซ้ำ ไม่ใช้ radial circle หลายก้อนจนอ่านเป็นลูกบอลฟุ้ง
- วางกล้องเป็นการเปิดมุมกาแล็กซีให้เห็นโครงสร้างเต็มก่อนค่อย push-in ผ่านแขนหนึ่งเส้น สร้าง parallax จากชั้นที่อยู่คนละระยะ
- ลด saturation และ bloom ของดาวส่วนใหญ่; เก็บแฉก diffraction ไว้กับดาวสว่างไม่กี่ดวง
- ทดลองทำ skybox/cubemap จาก Blender ได้เมื่อจำเป็น แต่ต้องวางให้ตรงทิศ/scale กับ Three.js และมี fallback procedural

**ผ่านเมื่อ:** galaxy view เห็นแกน แขน ฝุ่น และความลึกโดยไม่กลบชื่อ/ระบบดาว; ภาพยังคมเมื่อ resize

### P5 — เดินทางทะลุมิติแบบมีเรื่องเล่า

- ทำ director timeline เป็นช่วงชัดเจน: เปิดฉาก → เร่งเข้า portal → ผ่าน tunnel → คลายความเร็ว → เปิดกาแล็กซี → reveal ดาวลูกหมู-001
- ใช้ GSAP timeline และ CatmullRomCurve3 สำหรับกล้อง โดยแยกกล้อง/target และกำหนด easing ให้ไม่กระชาก
- Wormhole เพิ่มชั้นวงแหวนบิด, เส้นใย plasma และ star streak ที่วิ่งตามความเร็วกล้อง; ใช้สีม่วง/ชมพูเป็นหลักและ cyan เป็น accent เล็กน้อย
- ให้เสียงดนตรี/เสียง whoosh เข้าจังหวะกับการเร่งและ reveal; ให้ mute/reduced-motion ทำงานครบ
- ตัดเอฟเฟกต์ให้เป็นจังหวะ ไม่เปิด bloom/particle/streak ทั้งหมดพร้อมกัน
- เพิ่มปุ่มข้ามการเดินทางที่ไม่รบกวนภาพ และสถานะ loading หากมี asset ต้องโหลด

**ผ่านเมื่อ:** ดูรู้ว่าเดินทางไปไหนและถึงเมื่อไร, timeline จบทุกครั้ง, ปุ่มข้ามไม่ทิ้ง object/เสียง/กล้องค้าง

### P6 — ช็อตเปิดตัวดาวลูกหมู-001 และคำอวยพร

- ทำ reveal ดาวแบบ close-up ก่อนถอยให้เห็นระบบดาว/วงโคจรเต็ม
- ใช้ชื่อ “ดาวลูกหมู-001” เป็นป้าย 3D ที่อ่านได้หลายระยะ; ถ้าต้องการชื่อ “ข้าวหอม” ให้อยู่ด้านหลังฉากเฉพาะโหมดท่องกาแล็กซีตามที่ผู้ใช้ระบุไว้
- ถ้าต้องการตัวอักษร 3D จริง: แปลง glyph ไทยเป็น SVG outline ใน Inkscape/Figma แล้วใช้ `SVGLoader` + `ExtrudeGeometry`; ตรวจวรรณยุกต์/สระบน Prompt/Kanit อย่างละเอียด หาก glyph แตกให้ใช้ texture billboard คมชัดเป็น fallback
- กดคำอวยพรแล้วปล่อย starburst สั้น ๆ มีจุดสว่างกลางคม, เศษดาว/เส้นประกายบาง และจางลงอย่างรวดเร็ว; จำกัดจำนวนอนุภาคตาม quality tier
- เคารพข้อความและลำดับ popup เดิม; ไม่เขียนคำอวยพรใหม่เอง
- ทำช็อตจบที่หยุดนิ่ง 2–3 วินาทีสำหรับถ่าย/อัดคลิป

**ผ่านเมื่อ:** อ่านชื่อบน desktop/mobile ได้, burst ไม่บังข้อความ, เล่นซ้ำได้โดยไม่สะสมวัตถุหรือ memory leak

### P7 — ประสิทธิภาพและความคม

- ตั้ง quality tier ที่วัดได้จริง: low/medium/high; ปรับ DPR, จำนวน galaxy/background particles, shadow, postFX ตาม tier
- ตรวจ frame governor hysteresis ป้องกันสลับ tier ไปมา และอย่าสร้าง geometry ใหม่ทุก frame
- ลด overdraw ของ additive particles, หยุด update เมื่อวัตถุซ่อน, ใช้ BufferAttribute/InstancedMesh และ dispose texture/material ที่เลิกใช้
- lazy-load postFX/ฉาก cinematic/เสียงที่ยังไม่ใช้; แบ่ง chunk หาก bundle หลักใหญ่โดยไม่สร้าง flash หรือรอโหลดก่อนแสดงหน้าแรก
- ภาพคม: ใช้ DPR ตามความสามารถเครื่อง, MSAA สำหรับ render target ที่รองรับ, SMAA fallback ใน tier ต่ำ; คุม bloom ให้ต่ำ
- ทดสอบด้วย Chrome DevTools Performance/GPU และอุปกรณ์จริง; SwiftShader ใช้แค่ตรวจ screenshot/console ไม่ใช่ benchmark
- บันทึกขนาด bundle, เวลาโหลด, FPS median/1% low และ memory เท่าที่เครื่องมือรองรับ

**เกณฑ์เริ่มต้น:** desktop GPU เป้าหมาย 60 FPS; มือถือเป้าหมายอย่างน้อย 30 FPS ต่อเนื่อง โดยคงความคมและลดอนุภาคก่อนลดขนาด UI

### P8 — ตรวจและเตรียมลงโซเชียล

- ทำ preset ภาพ 16:9 (1920×1080) และ 9:16 (1080×1920) ด้วย safe area สำหรับข้อความ/ปุ่ม
- เพิ่ม `?cinema=1` ให้ซ่อน UI และรัน timeline ได้เอง; เพิ่ม `?mute=1`, `?quality=...`, `?ratio=9x16` ตามระบบเดิม
- Playwright จับภาพเปิดฉาก, galaxy view, star arrival, wish/fireworks ทุกขนาด พร้อมตรวจ console errors และ overflow
- ถ้าจะบันทึกวิดีโอ ให้ทำ `scripts/record.mjs` หรือใช้ OBS; อัดบน GPU จริงและล็อก seed/time ให้ภาพซ้ำได้
- ตรวจการใช้งานเพลงและสิทธิ์เผยแพร่ก่อนโพสต์วิดีโอสาธารณะ; การมีไฟล์ในเว็บไม่ได้หมายความว่ามีสิทธิ์ใช้เพลงบนทุกแพลตฟอร์ม

**ผ่านเมื่อ:** มีภาพ/คลิปแนวตั้งและแนวนอนที่อ่านได้, ไม่มี HUD debug, เพลง/เสียงควบคุมได้, บันทึกขั้นตอน export ไว้

## 5. เครื่องมือแนะนำ

| เครื่องมือ | ใช้กับงานนี้ | หมายเหตุ |
|---|---|---|
| **Three.js (ของเดิม)** | scene, camera, materials, shader, particles, instancing | ใช้ API เดิมและค่อยแยก renderer/director เมื่อจำเป็น |
| **GSAP (ของเดิม)** | camera director, reveal, UI transitions | timeline เดียวควบคุมช่วง cinematic และรองรับ skip |
| **Blender** | ปั้นหัวใจ/ดาวลูกหมู/โมเดล portal, ทำ HDRI/cubemap และ preview แสง | export glTF/GLB; ใส่เฉพาะ model ที่จำเป็นและ optimize ก่อน |
| **Substance 3D Painter (ทางเลือก)** หรือ **Blender Shader Editor** | ทำ albedo/normal/roughness maps | ใช้แผนที่ขนาดเหมาะ ไม่จำเป็นต้องซื้อถ้าทำ procedural ได้ |
| **Inkscape หรือ Figma + SVGLoader** | ทำ outline ตัวอักษรไทยสำหรับ extrusion | ตรวจ glyph สระ/วรรณยุกต์และ fallback |
| **NASA / ESA / Solar System Scope** | reference และ texture ดาว | ตรวจ license/เครดิตของแต่ละไฟล์ก่อนใช้งานจริง |
| **Three EffectComposer (ของเดิม)** | OutputPass, bloom, MSAA/SMAA และ postFX | ยังไม่ต้องเพิ่ม postprocessing library จนกว่าจะวัดแล้วว่าต้องใช้ effect เพิ่ม |
| **Playwright + สคริปต์ QA (ของเดิม)** | screenshot viewport, ตรวจ console/layout, deterministic flow | แยก visual check จาก benchmark performance |
| **Chrome DevTools / Spector.js** | ตรวจ GPU time, draw calls, shader, overdraw | ทดสอบบน GPU จริง ไม่ใช้ FPS ของ SwiftShader เป็นเกณฑ์ |
| **OBS Studio / FFmpeg / DaVinci Resolve หรือ CapCut** | จับและตัดคลิปแนวตั้ง/แนวนอน | เช็กเพลงและสิทธิ์ก่อนเผยแพร่ |

ไม่จำเป็นต้องใส่ทุกเครื่องมือพร้อมกัน: เริ่ม Blender เฉพาะชิ้น hero และใช้ Three.js ทำส่วนที่เคลื่อนไหว เพื่อควบคุมขนาดไฟล์/การโหลด

## 7. กติกา asset และขนาดไฟล์

- ใช้ KTX2 สำหรับ texture เมื่อ pipeline พร้อม; ใช้ WebP/AVIF สำหรับภาพประกอบ 2D ที่ไม่ต้องใช้ GPU texture compression
- GLB ใช้ Draco/Meshopt เมื่อโมเดลเริ่มใหญ่; อย่าเพิ่มโมเดลเพียงเพื่อให้คำว่า “3D” โดยไม่เกิดผลในมุมกล้องจริง
- ตั้งเป้าเริ่มต้น: ไม่มี asset เดี่ยวเกิน 5 MB, initial download ไม่เกิน 10 MB; บันทึกขนาดจริงก่อน/หลัง
- ทุก asset ภายนอกระบุ source, author, license, attribution ใน `CREDITS.md`
- ถ้าใช้ reference มาทำ procedural ใหม่ ให้บันทึกแหล่งอ้างอิงไว้ด้วย

## 8. วิธีทำงานและรายงานผลให้ผู้ใช้

1. เริ่มด้วย P0 แล้วทำทีละเฟส ไม่ข้ามไปเพิ่มเอฟเฟกต์ก่อนแก้สัดส่วนและแสง
2. ก่อนและหลังแต่ละเฟสให้เปรียบเทียบ viewport เดิม พร้อมระบุจุดที่เห็นเปลี่ยนจริง
3. รัน `npm run build` ทุกเฟส และ `npm run visual:qa -- --phase=pN`; เปิดภาพดู ไม่พึ่ง luminance metric อย่างเดียว
4. เมื่อเปลี่ยน material/asset ให้ตรวจ color space, alpha, depth sorting และ mobile GPU
5. ถ้าภาพดีขึ้นแต่ performance ลด ให้ลด particle/overdraw/shadow ตาม tier ก่อนลด resolution ที่ตาเห็น
6. อัปเดต `ASSETS_TODO.md`, `CREDITS.md` และสถานะเฟสเมื่อมี asset ใหม่หรือมีงานค้าง
7. สรุปใน PR/รายงาน: ไฟล์ที่เปลี่ยน, ภาพที่ตรวจ, build/console status, FPS บนเครื่องจริง (ถ้าวัดได้), และข้อจำกัดที่เหลือ

## 9. คำสั่งเริ่มต้น

```bash
npm run dev
npm run build
npm run visual:qa -- --phase=baseline
```

เปิด query flags ที่รองรับใน `src/core/quality.js` เช่น `?debug=1`, `?quality=high`, `?cinema=1`, `?mute=1`, `?skipintro=1`, `?ratio=9x16` แล้วตรวจว่าแต่ละโหมดทำงานจริงก่อนเพิ่ม flag ใหม่

## 10. ลำดับความสำคัญถ้าเวลาจำกัด

1. P1 จัดกล้อง/สัดส่วนให้วัตถุไม่หลุดเฟรมและ HUD ไม่บังฉาก
2. P2 ปรับแสงและพื้นผิวดาวให้คม/อ่านได้
3. P3 ทำวงโคจรให้มีความลึกและไม่รก
4. P5 จัดจังหวะเดินทางและ reveal ให้เป็นเรื่องเดียว
5. P4 เพิ่มรายละเอียดกาแล็กซีหลังจากองค์ประกอบหลักชัดแล้ว
6. P6–P8 เก็บช็อตจบ, performance และ social export

เริ่มทำ P0 และ P1 ก่อนเสมอ เพราะเพิ่มจำนวนดาว/แสง/โมเดลโดยยังไม่แก้ framing จะยิ่งทำให้ภาพแน่นแต่ยังดูไม่สวย
